Overview

The Five Contributors to Total Signal Delay

Length matching controls exactly one term in the delay budget: PCB trace propagation delay. The total signal flight time from transmitter die to receiver die is the sum of five distinct contributions — each with its own tolerance, temperature dependence, and measurement method.

T_total = T_trace + T_package + T_via + T_connector + ΔT_Dk

T_trace = L_trace × T_PD
T_PD_microstrip ≈ 5.9 ps/mm (FR4, εᵣ_eff ≈ 3.1)
T_PD_stripline ≈ 7.1 ps/mm (FR4, εᵣ = 4.2)
The bottleneck: DDR5 byte-lane length matching tolerance is ±0.9 ps (≈ 0.13 mm of trace). A single flip-chip BGA can have per-ball package delay variation of ±50 ps — 55× the PCB budget.
Design principle: Modern high-speed interfaces (DDR5, PCIe 5.0, 112G SerDes) include built-in training and equalization that compensates for package delay variation at link bring-up. For parallel buses without training, package delay must be characterized and compensated in the PCB layout using manufacturer-provided package delay tables.

01

Package Delay — The Dominant Hidden Term

Die-to-ball routing varies per signal, is rarely specified, and cannot be corrected after layout

What creates package delay?

Inside a BGA or QFP, each signal travels from the die pad through the package substrate or leadframe to the external ball/pin. This internal routing has a real propagation delay — typically 5–10 ps/mm for package substrate traces (εᵣ ≈ 3.5–4.5).

T_pkg = L_pkg_trace × √εᵣ_pkg / c

For L_pkg = 5 mm, εᵣ_pkg = 4.0:
T_pkg = 5 × √4.0 × 3.336 ps/mm
T_pkg ≈ 33 ps per signal

Package types and typical delays

Package typeT_pkg rangePer-ball skew
Wire bond QFP5–20 ps±5 ps
Wire bond BGA15–50 ps±15 ps
Flip-chip BGA (small)20–80 ps±30 ps
Flip-chip BGA (large SoC)50–200 ps±80 ps
WLCSP (wafer-level)2–10 ps±3 ps

Why datasheets rarely specify it

IC manufacturers characterize package delay during design but often omit per-ball tables from public datasheets. The information exists in the package model (IBIS, S-parameter, or package delay file) available from the vendor on request or in the IBIS AMI model archive.

How to obtain package delay data

  • IBIS model package section: The [Package] section of an IBIS file specifies R_pkg, L_pkg, C_pkg per pin. The L_pkg/C_pkg values can be used to infer propagation delay.
  • Package delay file (PDF/PDEL): Some vendors publish per-pin delay tables. DDR5 memory manufacturers increasingly provide this for address/data byte lanes.
  • Board-level de-embedding: Measure S-parameters of the test board and de-embed the PCB trace, leaving the package delay. Requires a known-good S-parameter model of the package.
  • TDR measurement: Time-domain reflectometry on a known-good sample can extract per-ball delay within ±5 ps using a calibrated 20 GHz TDR.

Compensating for package delay

If the package delay for signal A is 80 ps and for signal B is 40 ps, the required PCB trace length difference to equalize arrival times is:

ΔL_trace = ΔT_pkg / T_PD
= (80 − 40) ps / 7.1 ps/mm
= 5.6 mm (signal B needs 5.6 mm more trace)
02

Dielectric Constant Variation — Glass-Weave Effect

Up to ±15 ps/inch of skew from glass bundle vs resin pocket alignment, independent of trace length

Glass-weave structure of FR4

PCB laminates are made from woven glass cloth impregnated with epoxy resin. The glass bundles (Dk ≈ 6.0–7.0) and resin pockets (Dk ≈ 2.8–3.2) create a periodic Dk pattern with a pitch of ~0.4–1.0 mm depending on the fabric style. A microstrip trace running parallel to or exactly over glass bundles will see a higher average Dk than a trace running over resin pockets.

T_PD ∝ √εᵣ_eff

Over glass bundle: εᵣ_eff ≈ 4.5–5.0
Over resin pocket: εᵣ_eff ≈ 3.0–3.5

ΔT_PD/inch = (√4.75 − √3.25) × 84.7 ps/in
≈ (2.179 − 1.803) × 84.7 ≈ 31.8 ps/in worst case

Practical GWE skew: 5–15 ps/inch

Fabric styles and GWE severity

Glass fabricPitchGWE severity
7628 (standard)~1.0 mmHigh — avoid
2116 (medium)~0.6 mmMedium
1080 (fine)~0.4 mmLow
1035 spread-glassuniformVery low ✓
1067 spread-glassuniformMinimal ✓

GWE mitigation strategies

  • Rotate traces 7–10°: Angling traces relative to the glass weave axis averages the Dk over many glass/resin cycles. Most effective single mitigation step.
  • Spread-glass fabric: Request 1035 or 1067 style prepreg from the laminate supplier. Nearly eliminates GWE at modest cost premium (~5–15%).
  • Use stripline: Buried stripline is surrounded by resin and averages more Dk uniformly. GWE is reduced (but not eliminated) vs microstrip.
  • Meander patterns perpendicular to weave: If traces must be parallel to the board edge, route the meander sections perpendicular to the glass weave direction.

Manufacturing Dk tolerance

Even ignoring GWE, the bulk Dk of FR4 varies ±10% across a production panel and lot-to-lot. For a 6-inch (150 mm) trace at 180 ps/inch:

Nominal T = 150 × 7.1 = 1065 ps
±10% Dk → ±5% T_PD
ΔT = ±53 ps

DDR5 byte-lane budget: ±0.9 ps
→ Dk variation alone is 59× the budget

This is why DDR5 write levelling and read training are mandatory — they compensate for all non-controllable delay sources at link bring-up

03

Via Propagation Delay and Stub Effects

Each layer transition adds delay — and any unused stub length adds resonant delay variation

Via as a transmission line segment

A PCB via is a short section of coaxial-like transmission line: the via barrel (conductor) surrounded by the board dielectric. The propagation delay through a via is determined by its physical length and the effective dielectric constant of the surrounding material.

T_via ≈ h_via × √εᵣ_eff / c

h_via = 1.6 mm (standard 4-layer board)
εᵣ_eff ≈ 3.5 (board dielectric + air)
T_via = 1.6 × √3.5 × 3.336 = 9.99 ps ≈ 10 ps

Useful approximation: ~6 ps/mm of via length

Via stub delay and resonance

A through-hole via used as a blind transition has an unused stub below the signal layer. This stub acts as an open-ended stub resonator:

f_stub = c / (4 × L_stub × √εᵣ)

L_stub = 0.8 mm, εᵣ = 4.2:
f_stub = 300 / (4 × 0.8 × 2.049) = 45.7 GHz

L_stub = 3.2 mm (routing from layer 1 to 6
on a 10-layer board):
f_stub = 11.4 GHz — in PCIe 5.0 band!

Via delay budgeting

  • Through-hole via, 1.6 mm board: ≈ 10 ps per transition (signal + return via pair contributes effectively half due to differential mode cancellation)
  • Blind via, 0.4 mm depth: ≈ 2.5 ps — preferred for high-speed signals
  • Buried via: similar to blind — no stub, minimal delay
  • Backdrilled via: removes stub → eliminates stub resonance, delay reduced to active barrel only

Via-induced skew between signals

If signal A has 2 layer transitions and signal B has 4 layer transitions:

ΔT_via = (4 − 2) × 10 ps = 20 ps

Equivalent trace length to compensate:
ΔL = 20 ps / 7.1 ps/mm = 2.8 mm

Most EDA tools do not automatically account
for layer transitions in length-matching rules!
  • Use the same number of layer transitions for all signals in a matched group
  • If transitions differ, add equivalent trace length to compensate
  • Some EDA tools support "via equivalence" rules — enable them
04

Connector Propagation Delay and Pin-to-Pin Skew

10–200 ps per connector, with per-pin variation from non-uniform internal routing geometry

Connector delay sources

A connector is a discontinuity in the transmission line system. Even well-designed high-speed connectors have a physical signal path length through the contact and housing — this is real propagation delay, not just capacitive/inductive parasitics.

Connector typeT_connPin skew
SMA through-board40–80 ps±5 ps
PCIe edge finger (x16)20–40 ps±8 ps
DDR4 DIMM slot30–60 ps±15 ps
SAS/SATA backplane50–150 ps±20 ps
TE Z-PACK / ERNI80–200 ps±30 ps
FMC/FMC+ (FPGA)30–70 ps±20 ps

Why pin-to-pin skew matters

Within a single connector, pins at different positions have different effective path lengths. In a backplane connector, corner pins may be 2–5 mm longer than centre pins — at 7 ps/mm, that is 14–35 ps of intra-connector skew that cannot be corrected by PCB length matching.

How to handle connector delay

  • Request the connector manufacturer's S-parameter model or delay table — most Tier-1 connector vendors (Molex, TE, Amphenol) publish these for high-speed products
  • Include connector delay in the EDA tool simulation: import the S4P/S8P file as a component in your signal integrity analysis
  • Measure connector delay using 2-port TDR on known-good samples before finalising PCB trace lengths
  • Use connectors designed for the target data rate — a connector characterised to 12 GHz should not be used for PCIe 5.0 (16 GHz Nyquist)
Compensation: if T_conn_A > T_conn_B,
add to signal B trace:
ΔL = (T_conn_A − T_conn_B) / T_PD
05

Temperature and Frequency Dependence of Dk

FR4 Dk increases with temperature — a design passing at 25 °C may fail at 85 °C operating temperature

Temperature coefficient of Dk (TCDk)

The dielectric constant of FR4 increases with temperature due to the epoxy resin's molecular polarisability. A typical TCDk for FR4 is +0.001 to +0.004 per °C. Over a 60 °C temperature rise (25 °C → 85 °C):

ΔDk = TCDk × ΔT = 0.002 × 60 = +0.12

Nominal Dk = 4.2, at 85°C: Dk = 4.32

ΔT_PD / T_PD = ½ × ΔDk/Dk = ½ × 0.12/4.2 = 1.43%

For a 1000 ps signal: ΔT = ±14 ps at 85°C vs 25°C

Frequency dependence of Dk

Dk also decreases with frequency as polarisation mechanisms can no longer follow the field at high frequency. For FR4, Dk at 1 GHz ≈ 4.3, at 10 GHz ≈ 4.0, at 25 GHz ≈ 3.7. This means a signal's effective velocity increases with frequency — important for broadband SI simulation but less critical for matched-length single-frequency analysis.

Practical impact on timing budget

JEDEC DDR5 spec ±0.9 ps (bit-level)

Temperature Dk shift of ±14 ps over −40 to +85°C is 15× the bit-level budget — handled by on-chip DLL and write-levelling training

PCIe 5.0 at 32 GT/s Equalisation mandatory

SerDes link training and equalization compensate for Dk-induced ISI and frequency-dependent delay. No manual trace length compensation for Dk temperature effects is possible or needed.

Synchronous parallel bus (no training) Temperature margin required

Legacy parallel buses without built-in deskew must include timing margin for Dk temperature drift. Use low-TCDk laminate (Megtron 6, Isola I-Tera) for tighter timing margins.

Low-Dk laminates Megtron 6: Dk=3.6, TCDk <0.001

High-performance laminates reduce both absolute Dk (faster propagation) and TCDk (less temperature sensitivity). Mandatory for 112G+ SerDes and tight-timing parallel buses.

Real-World Timing Failures from Non-Trace Delay

Memory Subsystem

DDR4 LPDDR4 board — random bit errors at 3200 MT/s

All PCB trace lengths matched to JEDEC spec. Package delay tables for the specific LPDDR4 die variant showed ±45 ps per-ball variation within the DRAM package. Byte lane 2 had a 78 ps skew advantage over byte lane 5 — well outside the ±17 ps UI budget at 3200 MT/s. Fixed by adjusting PCB trace lengths to compensate using vendor package delay data. No board respin required — re-routed in place.

PCIe Interface

PCIe 3.0 x16 — lanes 8–15 failing eye mask

Lanes 0–7 (edge fingers near the card edge) passed eye test. Lanes 8–15 (further from edge) failed. Root cause: the PCIe edge connector had 22 ps higher propagation delay for the inner pins due to longer contact geometry. PCIe 3.0 training compensated for most of this but left 8 ps of unexplained skew that collapsed the eye at the receiver. Fixed by using a different connector with tighter pin-to-pin geometry specification.

High-Speed Parallel Bus

Custom 1 Gbps parallel interface — intermittent at temperature

8-bit parallel bus worked perfectly at 25 °C but failed randomly above 70 °C. Length matching was within ±0.2 mm. TDR measurement at temperature showed that two signals on different glass weave positions had 18 ps of GWE-induced skew that widened to 31 ps at 85 °C as the epoxy resin Dk increased more than the glass Dk. Fixed by adding 4 mm of serpentine to the faster signal and rotating traces 8° from the board edge on the next revision.

FPGA Design

LVDS camera interface — bit slip at startup only

A 12-lane LVDS image sensor interface produced correct images after warm-up but had bit-slip errors during the first 100 ms after power-on. Investigation found that the FPGA package delay for the LVDS input pins varied by 55 ps from the shortest to the longest lane — within the FPGA, not on the PCB. The FPGA's IDELAY calibration routine settled this at steady-state, but cold-start drift before calibration caused the bit slip. Fixed by extending the IDELAY calibration time and adding a cold-start reset.

Common Mistakes

Five Ways Timing Analysis Falls Short

M1

Equating "DRC clean" with "timing closed"

Symptom: EDA length-matching DRC passes; board fails timing at bring-up

EDA length-matching rules check PCB trace length only. They know nothing about package delay, connector propagation delay, or via count differences. A DRC-clean board can have 100+ ps of uncompensated non-trace skew.

Fix: After passing DRC, run a full SPICE or S-parameter simulation that includes package models, connector S-parameters, and via structures. A simulation-clean result with all contributors modelled is the actual closure criterion.
M2

Assuming package delay is symmetric within a BGA

Symptom: DDR byte lane 0 works; byte lanes 2 and 5 fail — all PCB traces matched

BGA die-to-ball routing is not symmetric. Data signals in different quadrants of the die may have very different package trace lengths. In a large processor, package delay can vary 100+ ps across the die — signal routing fanning out from different die corners has fundamentally different path lengths through the package substrate.

Fix: Request the package delay file from the IC vendor (often available as a ".pkg" or "delay_table" file alongside the IBIS model). Apply per-ball delay compensation in the PCB trace lengths. If the vendor cannot provide this, characterize the package delay with a TDR on prototype hardware.
M3

Matching trace lengths without equalizing via count

Symptom: Signals at different layer depths show timing skew proportional to layer difference

Two signals with identical PCB trace length but different via counts have different total propagation delay. At 6 ps/mm of via height, a 1.6 mm board thickness per transition means each additional via adds ~10 ps. Four extra transitions = 40 ps of skew — equivalent to 5.6 mm of unmatched trace length.

Fix: Add "via equivalence" constraints in the EDA tool (supported in Cadence Allegro, Zuken CR-8000, and Altium Designer). If via count must differ, add equivalent trace length to compensate: ΔL = N_extra_vias × T_via / T_PD.
M4

Routing high-speed traces parallel to the glass weave axis

Symptom: Timing margin is board-position dependent; some PCBs pass, others fail

When traces run parallel to the glass weave, adjacent signals may fall on entirely glass-rich or resin-rich weave regions — which determines their effective Dk. The per-panel position of a trace relative to the weave is random, so some boards pass and others fail depending on where their traces land on the glass weave.

Fix: Rotate critical traces 7–10° from the board edge (and thus from the standard glass weave orientation). Alternatively, specify spread-glass fabric (1035, 1067 style) in the PCB stackup notes — the fabricator will use flat-glass prepreg that eliminates the bundle/pocket pattern.
M5

Performing timing simulation at one temperature corner only

Symptom: Design passes timing analysis; fails in production at high ambient temperature

Dk and propagation delay increase with temperature. A design with 5 ps of timing margin at 25 °C may lose 12 ps of that margin at 85 °C as the FR4 Dk increases. If the design uses components with different TCDk values (e.g., different laminate materials or different via fill materials) the relative skew between signals may also change with temperature.

Fix: Run timing closure simulation at three temperature corners: cold (−40 °C), nominal (25 °C), and hot (85 °C or Tj_max). Use a laminate Dk/Df model that includes temperature dependence — IPC-4101C test data for your specific material. For production testing, verify timing margin at both temperature extremes on first-article boards.
Interactive Decision Tree

Diagnosing Timing Margin Loss

What is the failure pattern?

Are the failing signals all in the same byte lane, or spread across multiple lanes?

Is the failure rate board-position dependent — do boards from the same panel lot show consistent pass/fail?

Does the skew between failing signals increase with temperature?

→ Likely package delay variation within the IC

Request the package delay table from the IC vendor. Measure per-ball delay using TDR on prototype boards. Apply PCB trace length corrections to compensate for per-ball package delay differences. For DDR interfaces, check that the memory device's package delay is also included — both the controller and the DRAM contribute.

→ Likely connector pin-to-pin propagation delay variation

Obtain the connector S-parameter model and extract propagation delay for each pin position. Compare with the measured skew. If confirmed, either: (1) add PCB trace length compensation for the longer-delay connector pins, or (2) replace the connector with a higher-specification part that has tighter pin-to-pin geometry — check the connector manufacturer's "insertion delay variation" specification.

→ Likely via count mismatch between signal paths

Count the number of layer transitions for each failing vs passing signal. Calculate the via delay difference: ΔT = N_via_diff × h_board × √εᵣ / c. Add compensating trace length to the signals with fewer vias. Enable "via equivalence" rules in the EDA tool to prevent this in future revisions.

→ Likely glass-weave effect (GWE)

Panel position determines where traces land on the glass weave. Boards from the same panel position show the same GWE skew; boards from different positions show different skew. Mitigation: (1) rotate critical traces 7–10° from the glass weave axis in the current design, or (2) specify spread-glass prepreg (1035/1067 style) in the stackup for future revisions. For immediate relief, de-skew in firmware if a training mechanism is available.

→ Likely bulk Dk manufacturing variation (lot-to-lot)

FR4 Dk varies ±10% lot-to-lot. If two signals use different laminate materials or layers with different prepreg content, their propagation delay will differ by different amounts depending on the actual Dk of each board. Switch to a tighter-tolerance laminate (specify Dk tolerance in the fab drawing: ±5% or better) or add timing margin to accommodate the variation. Measure Dk using IPC-2141 coupon test on production boards.

→ Dk temperature coefficient causing differential delay growth

Two signals on different laminate layers or materials with different TCDk values accumulate different delays at temperature. Measure the dielectric material data sheet for TCDk values for each layer material. If different materials are used across layers (e.g., core vs prepreg with different resin content), signals on different layers may drift at different rates. Equalise layer materials or add temperature timing margin.

→ Insufficient timing margin — all delay sources at worst case simultaneously

The design is operating at the edge: each individual contributor (package, via, GWE, Dk) is within spec, but their worst-case combination consumes all available margin. Run a full statistical timing analysis (Monte Carlo with all delay contributors as random variables). Identify the two or three dominant contributors and reduce their tolerance — typically by using a tighter-Dk laminate, requesting package delay data and compensating, and equalising via counts.

Engineering Calculation Exercise

Scenario — DDR4-3200 byte lane timing closure

A DDR4-3200 design uses an SoC in a 17×17 mm flip-chip BGA. The package delay file shows: DQ[0] = 95 ps, DQ[7] = 55 ps. Both signals are routed as stripline on FR4 (T_PD = 7.1 ps/mm). DQ[0] has 2 via transitions; DQ[7] has 4 via transitions (board thickness = 1.6 mm, εᵣ = 4.2). The PCB traces are currently matched to the same length at 80 mm each. JEDEC DDR4 bit-level tolerance is ±2 ps.

  • 1. Calculate the via delay for each signal
  • 2. Calculate the total delay difference between DQ[0] and DQ[7] with current equal trace lengths
  • 3. Determine the required trace length adjustment to equalise total delay
  • 4. Is the remaining skew within the DDR4 ±2 ps bit-level budget? What additional measures are needed?

Solution

1. Via delay per signal: T_via_per_transition = h × √εᵣ / c = 1.6 mm × √4.2 / (299.79 mm/ps) = 1.6 × 2.049 / 299.79 = 10.94 ps per transition DQ[0]: 2 transitions → T_via[0] = 2 × 10.94 = 21.9 ps DQ[7]: 4 transitions → T_via[7] = 4 × 10.94 = 43.8 ps
2. Total delay difference with equal 80 mm traces: T_trace = 80 mm × 7.1 ps/mm = 568 ps (same for both) T_total[0] = T_trace + T_pkg[0] + T_via[0] = 568 + 95 + 21.9 = 684.9 ps T_total[7] = T_trace + T_pkg[7] + T_via[7] = 568 + 55 + 43.8 = 666.8 ps ΔT = 684.9 − 666.8 = 18.1 ps DQ[0] arrives 18.1 ps later than DQ[7]
3. Required trace length adjustment: DQ[7] needs to be delayed by 18.1 ps. Add trace to DQ[7]: ΔL = 18.1 ps / 7.1 ps/mm = 2.55 mm additional trace on DQ[7] New DQ[7] trace: 80 + 2.55 = 82.55 mm DQ[0] trace: 80 mm (unchanged) Verify: T_total[0] = 568 + 95 + 21.9 = 684.9 ps T_total[7] = (82.55 × 7.1) + 55 + 43.8 = 586.1 + 55 + 43.8 = 684.9 ps ✓
4. Is ±2 ps budget met? What else is needed? After trace compensation, the systematic delay is equalised. Remaining sources of skew (not yet addressed): • Dk manufacturing variation ±10% → ±0.5 × 0.1 × 568 = ±28.4 ps variation in T_trace At different temperatures, the relative Dk shift matters more than absolute Dk. Both signals are on the same board → correlated → common-mode Dk variation cancels. Differential Dk variation (e.g., from GWE) remains. • GWE (FR4, 1080 fabric, 0° routing): ±6 ps/inch × (80 mm / 25.4) = ±18.9 ps worst case With 7° trace rotation: reduced by cos²(7°) ≈ 0.97 → ±18.3 ps • Conclusion: after package + via compensation, the remaining budget is: ΔT_residual = GWE skew ≈ ±18 ps → far exceeds ±2 ps budget The ±2 ps JEDEC bit-level budget assumes DDR4's write-levelling and read-levelling training will compensate for all remaining skew at link bring-up. This is the correct assumption for DDR4/5 — the training is mandatory and compensates for package, via, GWE, and Dk variation to within the residual UI fraction. Additional measures needed: • Specify spread-glass prepreg (1035/1067) to reduce GWE to ±2 ps/inch • Rotate traces 7–10° from board edge • Verify write-levelling training completes within the SoC's DLL lock window • Run TDR verification on first-article boards to confirm compensation values
The ±2 ps JEDEC tolerance is achievable only because DDR4/5 training compensates for all non-trace delay contributors automatically. Without training (e.g., legacy parallel buses), the timing budget must include the full GWE + Dk + package + via skew — making ±2 ps timing closure physically impossible without exotic laminate and IC packaging choices.

JEDEC JESD79-4C (DDR4) DDR4 SDRAM specification Defines tDQSQ (±100 ps) and tDQS2DQ (bit-level ±100 ps for 3200 MT/s) — these include all delay contributors after training
JEDEC JESD79-5B (DDR5) DDR5 SDRAM specification Tighter timing than DDR4 — requires write levelling, read training, and DCA (duty cycle adjustment); PCB timing guidance in JEDEC JEP148
IPC-2141A Controlled impedance design guide Section 6 covers dielectric constant measurement, Dk tolerance, and temperature effects on propagation delay
IPC-4101C Laminate specification Defines Dk and Df specifications for FR4 and high-speed laminates including temperature and frequency test conditions
IBIS (I/O Buffer Information Specification) IC I/O model format The [Package] section specifies R_pkg, L_pkg, C_pkg per pin — used to derive package delay. IBIS 6.0+ supports [Package Model] with explicit per-pin delay entries
PCI Express Base Spec 5.0 §4.2 PCIe 5.0 electrical spec Requires equalization and link training for all PCIe 5.0 links — no static trace-length timing closure is possible at 32 GT/s; training handles all delay variation
Further Reading

References & Resources

Book

Signal Integrity Simplified — Eric Bogatin

Chapters 5–7 on propagation delay, Dk variation, and via structures. The definitive introductory reference for SI-aware PCB design with clear physical explanations of each delay contributor.

Book

High-Speed Digital Design — Howard Johnson

Chapter 4 covers board materials and dielectric effects including glass-weave effect, temperature dependence, and frequency dependence of Dk — still the most thorough treatment of PCB material SI effects.

App Note

Intel DDR5 Design Guide — Package Delay Tables

Platform-specific design guides from Intel and AMD include package delay tables for their processor BGA packages. Required reading before routing DDR5 on any of their platforms — the per-byte-lane delay compensation values are explicitly specified.

App Note

Isola: Glass Weave Effect and Spread-Glass Solutions

Quantitative GWE characterization data for standard vs spread-glass fabrics, including skew measurements at multiple data rates. Essential reference for specifying the correct prepreg style in the PCB stackup.

Tool

Cadence Sigrity / Ansys SIwave

Full-wave PCB SI simulation tools that can import package models, connector S-parameters, and via structures to produce a complete end-to-end timing analysis including all delay contributors.

Tool

Teledyne LeCroy / Tektronix TDR

20–50 GHz TDR instruments for measuring propagation delay of package, connector, and via structures in hardware. Required for de-embedding package delay when no vendor model is available.
