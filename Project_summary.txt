Project Summary
The site is for an engineering consultancy focused on product development, team development, process development, change management, hardware design review, EMI/EMC education, and engineering insights.
Main entry point:
index.html
It includes:
Company landing page
Service pages: product, team, process, change management
About, contact, industries, case studies, insights
Hardware Design Reviewer tool
EMI/EMC and hardware design learning portal
Login/register/admin UI pages
AI-assisted hardware review agent page
Technologies Used
Frontend:
HTML5
CSS3
Vanilla JavaScript
SVG icons embedded directly in HTML
Canvas API for simulations and waveform/engineering visualizations
localStorage / sessionStorage for theme, progress, checklist state, auth-like UI state
Responsive CSS media queries
No React, Angular, Vue, Tailwind, Bootstrap, or jQuery detected
Backend:
Node.js
Express.js
SQLite via better-sqlite3
helmet
cors
express-validator
nodemon for development
Backend package file:
package.json
Backend server:
server.js
Database:
SQLite database is created at runtime under:
pages/product_development/Reviewer/data/users.db
Uses a users table with name, email, mobile, location, company, role, dates, and status.
Main Functional Areas
The public website uses:
css/design-system.css
js/design-system.js
Shared UI features include:
Light/dark theme toggle
Mobile navigation
Scroll animations
Animated counters
FAQ accordion
Smooth anchor scrolling
The Hardware Reviewer area:
pages/product_development/Reviewer/index.html
Includes checklist pages for:

Signal integrity
Power integrity
EMI/EMC
Layout review
Thermal management
DFM/DFT/reliability
Shared checklist logic:
checklist-common.js
That logic stores checklist progress in localStorage and can export reports as CSV.
The EMI learning area:
pages/product_development/EMI2/index.html
It includes tracks, tutorials, tools, formulas, checklists, glossary, reference tables, and simulations. Core scripts are:
app.js
simulations.js
External Services / APIs
Detected:
Web3Forms contact submission in contact.html
Calendly link
Google Maps embed
Anthropic API call from browser in hw-review-agent.html
Important note: the AI review page stores the Anthropic API key in browser localStorage and calls Anthropic directly from the browser. That is okay for a prototype, but not ideal for production because API keys should normally stay server-side.
Current Backend API Status
The server currently implements:
GET /api/users
PATCH /api/users/:id/status
But these frontend pages expect APIs that are not currently implemented:
login.html expects POST /api/login
register.html expects POST /api/register
admin.html also expects POST /api/register
So login/register/admin add-user will not fully work until those backend endpoints are added.

Overall Assessment
This is a content-heavy static website plus prototype tools for hardware engineering review and EMI/EMC education. The frontend has a lot of useful UI already built, but the backend is incomplete for authentication and registration. The project would benefit from a proper backend auth flow, moving AI API calls server-side, and cleaning up a few broken/mismatched links such as some references to blogs/index.html while the repo uses Insights/index.html.
